# NewPaper 프로젝트 개발 규칙

## 1. 프론트엔드 (Frontend) 작성 지침
- **Vanilla Web Stack**: 외부 프레임워크 없이 `index.html`, `index.css`, `app.js` 구성을 유지합니다.
- **카테고리 구성**: `경제`, `글로벌`, `비즈니스`, `IT/과학` 4대 대표 필터 카테고리 지원 (`all`, `경제`, `글로벌`, `비즈니스`, `IT/과학`).
- **복수 카테고리 지원**: 기사는 복수 카테고리(`categories` 배열)를 가질 수 있으며, 필터 선택 시 매칭되는 모든 기사를 표시합니다.
- **뉴스 모달 구성**:
  1. 복수 카테고리 태그 및 헤드라인
  2. AI 종합 요약 (`overview`)
  3. 언론사별 기사 원본 링크 목록

## 2. 뉴스 수집, 클러스터링 및 AI 요약 (Collector & AI) 지침
- **RSS & 크롤링 수집**: 주요 언론사 공식 RSS 및 BeautifulSoup 웹 크롤링 방식으로 `경제`, `글로벌`, `비즈니스`, `IT/과학` 뉴스를 수집합니다.
- **카테고리 무관 동일 뉴스 판단**: Kiwipiepy 형태소 분석기(NNG, NNP 명사 2글자 이상)를 통해 카테고리 구분 없이 명사 키워드 교집합이 2개 이상이면 동일 이슈로 클러스터링합니다.
- **복수 카테고리 할당**: 클러스터 내 기사 출처 카테고리와 AI 분석 카테고리를 병합하여 다중 카테고리를 부여합니다.
- **출력 개수**: 최대 20개 뉴스 이슈(`MAX_CLUSTERS = 20`)를 선별하여 데일리 데이터를 생성합니다.
- **데이터 보존**: `RETENTION_DAYS` (기본 30일) 보관 주기를 준수하여 오래된 뉴스를 자동 정리합니다.

## 3. GitHub MCP & 에이전트 개발 협업 수칙
- 코드 작성 후 반드시 문법 오류 및 단위 검증을 수행합니다.
- 커밋 시 의미 있는 개별 단위로 커밋 메시지를 작성합니다 (`feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `chore:`).
